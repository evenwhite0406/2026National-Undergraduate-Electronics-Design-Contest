本文件由**逐行核对两端源码**得出。所有条目都附出处；无法从代码确认的标为 `TODO(待补充)`，未作推测。

## 2. 帧格式

所有帧都是 **ASCII 文本，用方括号包裹**：

```
[<payload>]
```

- 起始符 `[`，结束符 `]`
- payload 内**不得含有** `[` 或 `]`
- 两端解析器都是**非阻塞状态机**：只在收到 `[` 后开始收集，收到 `]` 后成帧

**缓冲区上限（两端不同，这是有意设计）**

| 端 | 常量 | 值 | 出处 |
|---|---|---|---|
| MSPM0 | `K230_FRAME_PAYLOAD_MAX` | **15** 字节 | `k230_link.c:8` |
| K230 | `LINK_RX_MAX_PAYLOAD` | **48** 字节 | `main.py:323` |

原因：MSPM0 收到的都是短命令（最长 8 字节），而 K230 需要接收较长的 `FC`/`FA` 前馈帧。**超限时整帧丢弃**，不会把残渣拼进下一帧（`k230_link.c:359-365`、`main.py` 的 `LinkReceiver.poll`）。

## 4. 上行帧（K230 → MSPM0G3507）

| 帧 | 格式 | 含义 | 出处（构造 / 发送） |
|---|---|---|---|
| **球位置** | `[±XXXX*]` | 钢球相对中心 O 的位置 | `main.py:3344` / `5269` |
| **R** | `[R3]` … `[R6]` | 任务 n 就绪 | `main.py:5068` |
| **R6 带目标** | `[R6,±XXXX]` | 任务 6 目标已锁定 | `main.py:3393` / `5080` |
| **L6** | `[L6,±XXXX]` | 任务 6 目标已锁、但球未稳定 | `main.py:3402` / `5078` |
| **PREP** | `[PREP3]` `[PREP4]` `[PREP5]` | 准备中的回执 | `main.py:5070` |
| **CENTER6** | `[CENTER6]` | 正在把球送回中心 | `main.py:5072` |
| **SET6** | `[SET6]` | 等待用户按 K230 板载键选定目标 | `main.py:5076` |
| **C6OK** | `[C6OK]` | 回中心完成 | `main.py:5082` |
| **RUN** | `[RUN3]` … `[RUN6]` | 已开始运行 | `main.py:5074` |
| **D** | `[D3]` … `[D6]` | 任务 n 完成 | `main.py:5267` |
| **RETURN** | `[RETURN]` | 正在返回起始位 | `main.py:5056` |
| **IDLE** | `[IDLE]` | 空闲 | `main.py:5060` |
| **ERR** | `[ERR,<原因>]` | 错误，如 `[ERR,NO_BALL]` | `main.py:5084` / `5263` |

### 4.1 球位置帧 `[±XXXX*]`

```
[+0123*]    表示 +12.3 mm
[-0045*]    表示 -4.5 mm
```

- **单位：0.1 mm**，原点为摆杆中心 O
- 格式固定为「符号 + 4 位数字 + `*`」，payload 恒为 6 字节
- 发送周期 **30 ms**（约 33 Hz），`main.py:319`
- 真实位置被**限制在 ±9899**（`main.py:3369`）

**哨兵值**（与真实位置共用同一字段）：

| 值 | 含义 | 出处 |
|---|---|---|
| `+9999` | 球丢失（`LINK_LOST_MARK`） | `main.py:320` |
| `+9998` | 任务 3 序列完成（`LINK_DONE_MARK`），连发 3 次 | `main.py:321`, `3374` |

> ⚠️ **已知隐患**：哨兵值与真实量程重叠（±999.9 mm）。K230 侧靠把真实值压到 ±9899 来回避碰撞，代码里有注释说明。这是**有意规避**，不是 bug，但移植到其它量程时需注意。

**丢球时会发 `+9999` 而不是停止发送** —— 因为"球丢了"和"链路断了"是两种不同故障，MSPM0 需要区别对待（`main.py:3358-3360`）。

### 4.2 任务 6 目标帧

| 帧 | 含义 | MSPM0 是否处理 |
|---|---|---|
| `[R6,±XXXX]` | 目标已锁定且球已稳定 | ✅ |
| `[L6,±XXXX]` | 目标已锁定但球未稳定 | ❌ **未处理，静默丢弃** |

> ⚠️ `[L6,...]` 在 MSPM0 端的解析器（`k230_link.c:223-333`）中**没有对应分支**，该帧会被直接忽略。
> 是否属于有意设计，代码无法判断 —— 见 `docs/TODO.md`。

## 5. 握手时序

```
【上电】
  MSPM0  K230Link_Init()                      状态 = OFFLINE
  K230   等待 UART4 命令（LINK_ENABLE = True）

【选任务】
  用户在 MSPM0 按 K1/K2 选任务，按 K3 确认
  MSPM0 → [P<n>]                              状态 = PREPARING
  K230  → [PREP<n>]  （任务 3/4/5）
          [SET6]     （任务 6，走另一条分支）
  K230   等待钢球稳定
  K230  → [R<n>]                               状态 = READY
          （任务 6 为 [R6,±XXXX]，带目标）
  MSPM0  OLED 显示 "READY: K3 START"

【正式开始】← 第二次按 K3，这是正式计时起点
  MSPM0 → [G<n>]                               状态 = RUNNING
  K230  → [RUN<n>]
  ⋯ K230 每 30 ms 发一次 [±XXXX*]

【任务 6 专有分支】
  MSPM0: 任务 5 完成或进入任务 6  → [C6]
  K230  → [CENTER6] → 球回中心 → [C6OK]
  MSPM0 → [P6]
  用户按 K230 板载按键（GPIO53）锁定目标
  K230  → [L6,±XXXX]（未稳定，MSPM0 忽略）
        → [R6,±XXXX]（稳定）

【结束】
  K230 → [D<n>]  或  [RETURN] → [IDLE]
```

### 5.1 超时与重试

| 项 | 值 | 出处 |
|---|---|---|
| MSPM0 重发未确认命令 | 每 **200 ms** | `k230_link.c:9` |
| MSPM0 判定链路离线 | **500 ms** 未收到任何帧 | `k230_link.c:10` |
| 离线后行为 | 清除 `ready_task`，状态转 OFFLINE | `k230_link.c:426-432` |
| K230 前馈采样超时 | 160 ms | `main.py` `CAR_START_FF_SAMPLE_TIMEOUT_MS` |

## 6. 状态机对照

| K230 的 `MissionController` | MSPM0 的 `K230LinkState` | 含义 |
|---|---|---|
| — | `OFFLINE` | 500 ms 无接收 |
| — | `IDLE` | 空闲 |
| 准备中 | `PREPARING` | 已发 P，等 R |
| 回中心中 | `CENTERING_TASK6` | 任务 6 回中心 |
| 选目标中 | `SETTING_TASK6` | 任务 6 等板载按键 |
| 就绪 | `READY` | 收到 R，等第二次 K3 |
| 运行中 | `RUNNING` | 收到 G，正在跑 |
| 回位中 | `RETURNING` | 收到 S，正在回起始位 |
| 出错 | `ERROR` | 收到 ERR |

两边状态语义**逐条对得上**，无冲突。

## 7. 无法从代码确认的部分

1. **`reference_accel` / `measured_accel` 的物理单位** —— `k230_link.h:40` 注释写 "car speed-percent/s"，但 K230 侧解析后只保存、**从不读取**，无法验证。且 MSPM0 侧也未说明如何计算这两个值。
2. **`[L6,...]` 是有意忽略还是漏实现** —— 见 4.2。
3. **`[PREP6]` 是否会出现** —— K230 用 `"PREP%d" % event[1]` 发回执，若 `event[1]` 取到 6 就会发 `[PREP6]`，而 MSPM0 只接受 `PREP3`–`PREP5`（`k230_link.c:272`）。代码路径上任务 6 走的是 `SET6` 分支，但**无法静态断定 `event[1]` 不会取 6**。
4. **任务 1–8 的具体赛题要求与评分点** —— 代码里只有任务名，不含题目描述。
